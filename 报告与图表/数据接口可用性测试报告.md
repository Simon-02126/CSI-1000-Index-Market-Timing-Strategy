## 二、逐个接口测试详情

### 2.1 baostock —— ❌ 不可用（最重要的发现）

包本身装得上（`pip install baostock` → `0.9.40` 成功），但**服务器连不上**：

```
第 1 次 login ... timed out / 接收数据异常，请稍后再试。
    code=10002007 msg=网络接收错误。   (60.1s)
第 2 次 login ... 服务器连接失败，请稍后再试。 / timed out
    code=10002007 msg=网络接收错误。   (81.0s)
第 3 次 login ... 服务器连接失败，请稍后再试。 / timed out
    code=10002007 msg=网络接收错误。   (81.0s)
```

`code=10002007` 是 baostock 传输层的接收错误，等价于「TCP 通了但拿不到响应」或「连接被拦」。三次全部在 `bs.login()` 阶段失败，**连历史数据查询都没跑到**。

需要区分两种可能：

- 如果是**本机网络/防火墙**问题 → 换网络环境再试，现行脚本仍可用；
- 如果是 **baostock 服务器下线/限流** → 现行数据链源头就断了，必须换源。

**无论哪种，都不建议把生产链继续压在 baostock 上**——它是个免费单点服务，没有 SLA，且本次已实测不可达。

## 三、对数校验（文档遗留事项 2 的全部完成）

文档要求：与现有 CSV 比对最近 10~20 个交易日，**相对误差 < 万分之一（0.01%）**。

### 3.1 量价：东财 http 通道 vs `input/中证1000_000852.SH.csv`

逐日比对 2026-09-21 ~ 2026-10-21 共 18 个交易日：

| 字段 | 最大相对误差 | 结论 |
|---|---|---|
| 收盘价 | **0.000066%** | 一致（仅四舍五入） |
| 开盘价 | 同 | 一致 |
| 成交额 | **0.000177%** | 一致 |
| 换手率 | 0.5974%（绝对差 ≤ 0.01 pct） | 一致（东财只给 2 位小数） |
| **成交量** | 99.000000% | **单位差：东财是「手」，项目 CSV 是「股」，固定 ×100** |

成交量逐日精确 100 倍，例如 2026-10-21：东财 `175,326,782` 手 × 100 = `17,532,678,200` 股 = 项目 CSV 值。**不是数据错误，是单位换算**。

另外顺带确认：项目 CSV 的 `均价(元)` = 成交额 ÷ 成交量（10-21：2.804064e11 ÷ 1.753268e10 = **15.9934**，与 CSV 完全一致）。

## 六、未覆盖 / 待办

1. **baostock 到底是本机还是服务端问题**：只在本机测过，未换网络验证。建议在另一台机器/另一网络再试一次，确定是「环境问题」还是「服务下线」。
2. **iFinD 通道未测**：商业授权，本机没有。
3. **北交所市场规模（`code=9`）的免费源未找**：本策略不影响（用 `code=11`），但若以后要算 `code=14` 才需要补。
4. **两融 BSE 行**：项目 CSV 有 `BSE` 交易所行（北交所两融），akshare 的两融接口只覆盖沪深，北交所两融需另找（对中证1000 的 slow 视图无影响）。
5. **历史回补验证**：本次只比对最近 5~18 个交易日，未做全历史（2012 起）的逐日对数校验。如果要把东财 http 设为主数据源，建议再做一次全历史对齐（东财中证1000 从 2005-01-04 起，比项目 CSV 的 2012-01-04 更早，所以是「回补」而非「丢失」）。
