## 关于这个仓库（公开版）

这是项目的**代码与研究归档**，不是一份可以直接 `git clone` 就跑的完整环境。取舍如下。

### 有什么

`core/`（通用逻辑）、`live/`（每日实盘链路，只保留 SQLite 那一代）、`dashboard/`（看板）、`db/schema.sql`
（库结构）、`models/`（2026 年那一折的模型检查点）、`archive/research` + `archive/reports`（全部研究脚本）、
`archive/signals/_train_out/`（研究实际用过的 6-seed 逐年信号，**生产链路也读这里**）、`05_报告与图表/`（全部报告）。

### 没有什么，以及为什么

| 缺的东西 | 原来在哪 | 为什么不放 |
|---|---|---|
| 指数日线、两融、市场规模、期权/期货持仓等原始数据 | `input/` `data/` | 来自 CSMAR 与付费数据源，**许可不允许再分发** |
| `timing.db`（约 13 MB） | `db/` | 内含全文行情，等同于把上游数据再分发一遍 |
| 华泰证券研报 PDF | `07_参考资料/` | 研报有版权 |
| 旧 CSV 链路（`bootstrap` / `fetch_daily` / `portfolio` / `report` / `run_daily` / `signals`） | `live/` | 两代实现并存只会误导；SQLite 那代已完全覆盖 |
| `state/`、`output/` 下的运行产物、`archive/logs/` | — | 可再生成，且含本地路径 |

### 怎么跑起来

1. 按 `data/README.md` 把原始数据放回 `input/` 和 `data/`（列名与 `input/*字段说明.txt` 对齐）。
2. 建库：`python db/import_csv.py`（CSV → SQLite），或者日常用 `python live/db_update.py --fetch` 增量更新。
3. 自检：`python _paths.py` → `python core/selftest.py`。

### 关于训练集 / 验证集 / 测试集（重要）

模型是**按年滚动训练**的（`core/model_io.py`）：预测第 Y 年时，训练集 = Y-4 年至 Y-3 年初，验证集 = 之后到 Y-1 年末，
1 月 1 日之前留 11 个交易日的 embargo 防泄漏。

因此：

- **`models/` 里只有 2026 年这一折的检查点**，不是"只训了 2026"，而是**只有 2026 年这一折是真正的样本外**，
  其余年份的检查点是训练过程中的中间产物，留着没有意义。
- 相应地，**2019–2025 的绩效属于样本内**（会偏乐观），**2026 年才是干净的样本外证据**；
  报告里所有分年表格都能看出这个分界。
- 要复现全历史，需要自己补训 2019–2025 各折（`python live/model_registry.py ensure-all`，
  2 个 view × 6 seed，约 30 秒/seed）。

### 这不是实盘业绩

所有数字都来自**回测**或**模拟盘**。模拟盘按 T+1 集合竞价挂单、单边 3bp 成本计量，但仍不等于真实成交。

代码与文档用 MIT（见 `LICENSE`），请把 `<AUTHOR>` 换成你的名字；**数据不在许可范围内**。
过拟合检验的做法与结论见 §六。

## 零点一、训练与回测怎么跑（3 步）

```powershell
cd 中证1000择时_公开版
python _paths.py                     # 1) 自检：路径 / 数据源是否全部解析正确
```

逐项比对累计 / 年化 / 夏普 / 回撤 / Calmar / 换手 / 成本 / 调仓 / 分年，任何一项对不上就 exit 1。
报告里的每个数字都出自同一条链路（`core/selftest.py` 逐项核对，任一不符 exit 1）。

要重画净值图：`python archive\reports\4.6_最终版计算与报告\report_final.py`（写 `05_报告与图表/净值走势图_策略vs基准.png`；
该脚本是**旧口径** k=5，图仍可用，但数字与现行报告不同）。
需要 Word 版说明文档：`python archive\reports\4.6_最终版计算与报告\md_to_docx.py`（依赖 python-docx）。

输出：控制台 5 张表（因子 IC / 核心绩效 / 交易级 / 分段超额 / 分年统计），
净值图写到 `05_报告与图表\净值走势图_策略vs基准.png`。
需要 Word 版说明文档时：`python archive\reports\4.6_最终版计算与报告\md_to_docx.py`（额外依赖 python-docx）。

## 零点二、实盘模拟盘怎么跑

### 首次：把账本从历史回填到今天

```powershell
python live\db_update.py --fetch   # 建库→重建特征→（缺则）训练年度模型→冻结信号→按 ETF 开盘价记账
python live\db_update.py --rebuild-oos     # 从 2026-01-01 起重放账本（回补过历史数据时用）
```

### 每天（收盘后 21:00 之后，两融已挂网）

```powershell
python live\db_update.py --fetch    # 抓数入库 → 重建特征 → 冻结信号 → 按 ETF 开盘价记账
#   或直接点看板上的「更新交易」按钮（同一条链路，dashboard/server.js → spawn python）
```

| 时点 | 做什么 | 数据 |
|---|---|---|
| 15:00 收盘 | 量价 8 通道定稿 | 东财 push2his（**必须 http**） |
| 15:30 | 中金所前 20 会员持仓 → IF 多空比 | akshare `get_cffex_rank_table`（须 `rank<=20`） |
| 20:00 | 沪深板块市值 / 挂牌数 | akshare `stock_sse_deal_daily` + `stock_szse_summary` |
| 21:00 | 两融余额（T+1 披露，当日能拿到前一日的） | akshare `stock_margin_sse/szse/bse` |
| **T+1 09:15~09:25** | **按目标仓位集合竞价挂单** | — |

产物：
- `db/timing.db` 里的 `ledger`（逐日账本，append-only）、`signal_freeze`（信号冻结证据）、
  `model_files`（模型指纹）、`ingest_log`（抓取留痕）；看板直接读 `v_nav` / `v_features_final`。

### 三条必须知道的规则

1. **模型只在缺的时候训练**：`live/model_registry.py` 检测 `models/{view}/{view}_{年}_s{seed}.pt`，
   有就加载复用，没有才训练并保存。每年最后一个交易日之后第一次运行会自动补训练新年度。
   数据历史被修正时 `ensure` 会提示 `建议 --retrain`（检查点里存了训练窗口的数据指纹）。
2. **`core/replay.py` 是唯一的绩效口径**：T 日收盘出信号 → T+1 开盘价成交 → 当日收盘盯市，
   且**只在目标仓位变化时交易**（不每天拉回目标，否则白付漂移成本：换手 17.09→18.9、成本 0.51%→0.57%）。
   历史上那个 `pos.shift(1)*ret` 的回测引擎，把整根 close-to-close 收益归给「前一日决策的仓位」，
   等于假设隔夜跳空时你已经在目标仓位上 —— 现实中做不到，**该口径已作废**。
   两种口径聚合接近（旧 1.22 / 新 1.19），但单年可差 ±4~6pct（如 2020 春节后低开建仓，真实路径多赚 2.25pct）。
3. **历史数据被回补/修正后要重放账本**：默认只追加当天一行；如果补过历史（两融/规模回填），
   用 `python live\db_update.py --rebuild-oos`（从 2026-01-01 起重建），否则账本会与信号不一致。
   原因：死区是**路径依赖**算子，「上一笔实际仓位」不同，后面每一笔都可能不同。

## 零点三、数据库与看板

### 3.1 为什么会有 `db/timing.db`

2026-10-27 之前，数据都在 `input/中证1000_000852.SH.csv` 一张表里，靠"每次抓数直接覆写"维护。
那次出过一个真问题：**盘中快照被当成收盘价写进了主数据**。所以现在改成 SQLite 四层结构：

| 层 | 表 | 作用 |
|---|---|---|
| raw | `index_daily` / `etf_daily` / `margin_daily` / `market_size_daily` / `cffex_rank_raw` | 抓下来的原始数据 |
| derived | `features_main` / `emotion_panel` / `if_sentiment` | 由 raw 重建的入模特征 |
| state | `ledger` / `signal_freeze` / `model_files` | 账本、信号冻结证据、模型指纹 |
| meta | `ingest_log` / `quality_check` | 每次抓取的留痕、自检结果 |

两条铁律：

1. **训练/回测/信号只读 `v_features_final`**（= `features_main JOIN index_daily` 且 `status='final'`），
   盘中快照（`provisional`）在视图层就被挡掉，模型根本接触不到。
2. **两融用 `effective_date = T+1` 表达披露滞后**，查询时按 `effective_date <= T` 取，而不是靠"记得滞后一天"这种纪律。

补一条抓数侧的约定：**"已最新"必须同时看日期和状态**。盘中（15:10 前）抓过的当日 bar 会标
`provisional`，如果只按 `MAX(date) == 今天` 判"已最新"就跳过，那根 bar 永远不会被 `final` 覆盖，
`features_main` 会停在昨天、账本随之停摆。`live/db_fetch.py` 现在的做法是：末日等于今天但状态仍是
`provisional` 时，从当天起重抓一次；这也让任何历史遗留的 `provisional` 行在下一次运行时自愈。

详见 `db/表结构说明.txt`（含每张表字段、当前行数、维护约定）。

### 3.2 看板怎么开

```powershell
cd 中证1000择时_公开版
双击 dashboard\打开看板.bat            # 或： node dashboard\server.js --port 7100
```

「更新交易」会 `spawn` Python 跑 `live/db_update.py --fetch`，解释器取环境变量 `PYTHON`，缺省用 PATH 上的 `python`：

```powershell
$env:PYTHON = "C:\Python312\python.exe"   # 仅当 PATH 上的 python 不是你要用的那个时才需要
```

> 为什么留这个开关：Windows 上 PATH 里的 `python` 常是 Microsoft Store 的 0 字节转发桩，
> 执行直接 `exit 9009`，还会顺手弹应用商店。这时设 `PYTHON` 指向真实解释器即可。

## 一、这个项目是什么

给**中证1000 指数（000852.SH）** 做日频择时，只做多、仓位 0~100% 可调。三块信号分工：

| 板块 | 数据 | 作用 |
|---|---|---|
| **量价（pv）** | 150 交易日 × 8 通道（开高低收 / 均价 / 量 / 额 / 换手率） | 与资金面共同决定**基准仓位**（三档 0 / 50% / 100%） |
| **资金（slow）** | 两融余额、融券余额、板块总市值、上市股票数、融资净买入（10 维静态） | 同上 |
| **情绪（IF）** | 沪深300 股指期货前 20 会员持买单量 / 持卖单量 的 250 日滚动分位 | **仅当基准仓位在半仓档时**，替换为连续仓位 |

## 六、过拟合检验（PBO / CSCV）

完整报告：`05_报告与图表/PBO_CSCV_过拟合检验.md`；图：`PBO_CSCV_过拟合检验.png`；
代码：`archive/research/4.6_PBO过拟合检验/pbo_cscv.py`（检验）+ `pbo_figure.py`（出图）。

**为什么做**：夏普 1.19 里有多少是运气，光看单一回测曲线回答不了。用 CSCV（Bailey et al., 2014）
把样本切成 S 个连续块、枚举 C(S,S/2) 种"一半当样本内、一半当样本外"的切分，每次在样本内挑夏普最高的配置，
看它的样本外排名落在哪 —— **PBO = 挑出来的冠军在样本外落到中位以下的概率**。

**候选集**（参数一律走 `core/strategy.py` + `core/replay.py`，不另写回测引擎）：

| 层 | 维度 | 组数 |
|---|---|---|
| 参数层 | 窗口 × 三档阈值 × 众数 k × 饱和开关 × pv 权重 × 情绪开关 × 网格/死区 | 1152（去重后 864） |
| 结构层 | 上述 × 6 种量价口径（main / h10 / h20 / d5_10_ic / d5_10_mse / d5_10_20_ic） | 288 |

**结果**（S=16，12870 次切分）：

| 检验 | PBO | 说明 |
|---|---|---|
| 参数层（出厂口径内） | **11.9%** | S=10/20 分别 15.9% / 18.4%，稳健 |
| 结构层（含选口径） | **29.7%** | S=10/20 分别 39.7% / 38.1% |
| 只比口径、参数固定 | 进样本外前 3 名 **74.1%**（随机 50%） | 选口径这一步是稳的 |
| 每口径各自调参后再比 | 进前 3 名 **51.4%** | 与随机无异 |

- 出厂配置在参数层排 **65/1152**、结构层排 **8/288** —— 不是第 1，说明当初并没有对着全样本 argmax 挑参数。
- Deflated Sharpe（考虑 864 次多重比较后）= **0.87**。
- **结论**：在既定口径内调参不算过拟合（12%）；剩下的约 30% 全部来自"选哪个量价口径 + 选完再调参"。
  口径梯队内部本来就分不出高下（main 1.192 vs 最好的 d5_10_20_ic 1.233，差 0.04，而同一时点不同口径的极差平均 0.92），
  所以**不要再在口径上继续调**，那是负期望的活。

```powershell
python archive\research\4.6_PBO过拟合检验\pbo_figure.py     # 出四联图
```

### 7.4 可迁移设计（`_paths.py`）

**原始脚本用的是硬编码绝对路径，直接拷走跑不通。本包已全部改成相对解析：**

- 根目录 `_paths.py` 是唯一路径入口，用 `Path(__file__).resolve().parents[1]` 定位项目根；
- 每个脚本头部有一小段自举代码，**向上逐级查找 `_paths.py`**，找到后 `import _paths as _P`；
- 正文里的 `BASE` / `DATA` / `input` / `TRAIN` / `OUT_DIR` 等常量全部指向 `_P.*`。

### 7.5 输出约定

- **执行引擎**：`core/replay.py`。T 日收盘出信号 → **T+1 开盘价成交** → 当日收盘盯市；
  只在目标仓位变化时交易，不做日度再平衡。
- **交易成本**：单边 3bp，按 `abs(成交后仓位 − 成交前实际仓位) × 成交后权益` 计提，当日从权益里扣。
- 年化换算：`日对数收益均值 × 252`；夏普 = 日收益均值 ÷ 日收益标准差 × √252。
- **绩效区间**：`2019-06-04 ~ 2026-09-30`，1780 个交易日 / 7.06 年（报告口径）。
- **账本区间**：DB `ledger` 从 `2026-01-05` 起（换标的为 ETF 512100 后的新账本）。
- **众数平滑窗口 `K_MODE = 3`**（2026-10-27 由 5 调整；`core/strategy.py:23`）。
- 仓位落地的两步换算不可颠倒：**先** 5% 网格（`round(p/0.05)*0.05`），**后** 10% 死区
  （与当前持仓差 <10% 就不动）。死区必须大于网格步长，否则等于没有死区。
- 参数全表在 `core/strategy.py` 顶部常量区；报告附录有同一张表。

## 九、关键结论速查

**成立的部分**（replay 引擎 / k=3 / T+1 开盘成交口径）

- 三块合起来：M3 基准夏普 0.71 → **1.19**，回撤 -33.9% → **-25.1%**，
  相对买入持有超额 t = 2.69；相对 M3 基准的 36 组 seed Δ 夏普均值 **+0.279**、正占比 97%
- 情绪层的增益 **100% 来自时点选择**（不是降杠杆）：同均仓的恒定折扣对照夏普分毫不变
- 情绪只动半仓档是正确的：四桶归因里半仓档内两桶 +0.648 log，两个极端桶 **-0.207 log**
- 安慰剂 70 次循环平移全部低于实际（p ≈ 0.014）
- 成本不是问题：20bp（报告口径的 6.7 倍）下夏普仍有 1.024；仓位量化到 25% 网格 1.206（不降反升）
- 执行速度是**唯一**对精度敏感的一环：T+2 开盘 −0.120 夏普、T+3 −0.169，所以必须 T+1 竞价挂单

**不成立 / 风险**

- **过拟合检验已做**（见 §六）：参数层 PBO 11.9%（S=10/20 → 15.9%/18.4%）、结构层 29.7%、DSR 0.87；
  出厂配置排 65/1152，不是全样本最优 —— 这是正面证据。剩余风险集中在"选口径 + 选完再调参"，不在参数本身。
- 36 组 seed 的 **Δ 夏普最小值 −0.017**（约 3% 的组合会略微变差）→ 下限贴着"没改善"
- 情绪因子在衰减：分年 IC 2025 年 −0.299、2026 年 −0.096；OOS 2025-2026 增量 **−0.159 夏普**
- 2021 年结构性跑输 **−14.5pct**（低波慢牛，日均仓位被压到 22.8%）
- 不覆盖杠杆踩踏式闪崩：2024 年初小微盘流动性危机里该段日均仓位仍有 64%
- DB 层新增的口径风险：`margin_daily` 只维护近 90 天窗口、更早以 CSMAR 底档为准，
  跨源拼接处可能出现量级漂移；`provisional` bar 若被误当 `final` 会污染训练（已用视图隔离）

**已否决、不用再试的方案**

20 日标签（IC 变负）｜滚动 z-score（破坏趋势）｜合成后重排序（0.66→0.46）｜仓位层加权（0.662→0.341）｜波动率目标（0.58→0.35）｜条件期望映射（-0.21/-0.34）｜三期 IC（OOS pooled -0.094）｜双期 MSE 作合并输入（0.48~0.51 < 0.55）｜把情绪当第三打分项（0.696~0.848 全低于 0.758）｜软减 S1/S2（0.986/0.961 < 硬清零）｜Aup 只加不减（0.849，本质加杠杆）｜A0+V 叠加（年化与 Calmar 都低于 A0）｜冷却 20 日（退化到 0.74~0.76）｜复合触发加任何确认条件（掉 0.09~0.26）
